# Audio "Console" Surface — UI/UX Improvement Proposal

_Polish + targeted-restructure pass on the freshly-merged Console redesign (PR #111/#112). Audit-only — no files were edited. All proposals are front-end-only, token-disciplined, hold across Studio/Graphite/Bone, and respect the no-scroll fixed-height posture at 2560×1440 (primary) and 1920×1080 (fallback)._

## Executive summary

The rebuilt Console is a strong, dense, single-accent surface, but the merge shipped with a small number of genuine **rendering and correctness defects** sitting next to a broader layer of **consistency drift**. Two issues are outright bugs: the inspector send/action controls reference five CSS classes that are **never defined** (so they render unstyled), and the monitor bar's **"Listen" button silently drives the −20 dB Dim** off the same flag. Beyond those, severity is invisible in fixed chrome (errors never turn red despite an existing `tone` field), the most dangerous latched state — **solo** — has no persistent indicator or clear-all accelerator, the **master monitor level has no keyboard access at all**, and the redesign forked the token system (a new `--bg/--fg/--accent` set living beside the legacy `--audio-*` family, plus ~75 hardcoded font literals that fall back to the wrong physical font). The highest-leverage work is a handful of small, high-confidence fixes (wire the missing CSS, de-trap Listen, drive `status.tone` into the chrome, mono-ize the serif send readout, fix the lane-toggle legibility) followed by two targeted restructures (a persistent solo indicator + accelerator, and reclaiming dead vertical/horizontal layout band).

**Totals:** 21 findings kept (15 polish, 6 restructure). 0 require new engine/protocol/OSC data — everything here is implementable in the front end as defined by the architecture boundary. 1 candidate was refuted and dropped.

### 1. Correctness / rendering defects (shipped in #111/#112)

| ID  | Title                                                                                       | Impact   | Effort | Kind   |

| C01 | Inspector send/fader/action controls render unstyled — referenced CSS classes never defined | **high** | S      | polish |
| C02 | "Listen" and "Dim" are the same latch — pressing Listen silently attenuates the bus −20 dB  | **high** | S      | polish |

**C01 — Five missing inspector CSS classes** · `AudioInspectorChannelSendActions.tsx`, `AudioInspectorOutputView.tsx`, `AudioInspector.module.css`
Both files reference `styles.inspectorFaderCard`, `inspectorFaderHead`, `inspectorFaderTicks`, `inspectorSendSlider`, `inspectorActionRow` (10 usages), but a repo-wide check confirms **0 definitions** in any audio `.module.css`. Each resolves to `undefined`, so the "Send to {output}" head, the dB tick scale (−∞ −40 −20 −10 0 +6), the send slider width, and the Mute/Solo/Unity row fall back to raw block flow with default browser buttons — visible as bunched glyphs and plain grey pills in the 2560 inspector crop. A similarly-named but unused `.inspectorSendActions` (line 447) confirms this is a wiring miss, not an alternate selector.
**Proposal:** Add the five classes to `AudioInspector.module.css`, token-only, mirroring sibling vocabulary already in that module: `.inspectorFaderCard` = flex column, gap 8px, padding 14px, 1px `var(--line)`, `var(--radius-sm)` (=8px, confirmed real), `var(--bg-2)`; `.inspectorFaderHead` = baseline space-between, ~11px mono, `var(--fg-3)`, `strong → var(--accent)`; `.inspectorFaderTicks` = flex space-between, ~8.5px mono, `var(--fg-3)` (even tick distribution); `.inspectorSendSlider` = `width:100%` (required — `AudioSliderControl` horizontal sliders measure their own rect and do not self-stretch); `.inspectorActionRow` = `grid repeat(3, minmax(0,1fr))`, gap 6px, child buttons reusing the lane-toggle treatment (height 28px to match the nearby `.unsupportedToggleRow`, radius 6px, `var(--bg-3)`/`var(--fg-3)`, with the **same** `data-active` mapping the lanes already use — `mute → var(--danger)`/#fff, `solo → var(--accent)`/`var(--bg)`). Not a multi-hue reintroduction — it is the identical monochrome-amber + clip-red vocabulary the shipped lanes use. Footprint ≤ current default buttons → no scroll regression at 2560 or 1080.

**C02 — Listen secretly drives Dim** · `AudioMonitorBar.tsx`
`setControl('listen')` and `setControl('dim')` both call `onUpdateMixTarget({ dim: !dim })`, and **both** buttons render `aria-pressed={dimOn}` + `data-active={dimOn}`. Pressing the non-destructive Listen/Cue engages the −20 dB dim and lights both buttons; the Dim neighbor uses `.controlWarn` which paints **danger red + glow**, so pressing Listen makes a red destructive-looking button light up — the wrong control confirming the action. Listen/cue is genuinely absent from the engine surface (`AudioMixTargetUpdateRequest` has only volume/mute/dim/mono/talkback), and no shortcut/palette action references Listen.
**Proposal (preferred):** **Remove the Listen button** so the cluster reads honestly as Dim / Mono — both real engine flags; the canonical hierarchy test already treats Dim/Mono/Talkback as the owned set, so nothing breaks and ~80px is freed in the `flex:0 0 auto` cluster (safe at 2560/1080, all themes). Acceptable alternative: keep one button labelled "Dim" only (drop the `listen` branch). **Do NOT** ship the "just decouple the active states" half-measure alone — a Listen button that no longer reflects `dimOn` but still calls `onUpdateMixTarget({ dim })` would preserve the silent −20 dB attenuation while removing its only (accidental) feedback. Wiring a real listen/cue flag is **out of scope (engine).**

### 2. Color, contrast & legibility

| ID  | Title                                                                                   | Impact   | Effort | Kind   |
| --- | --------------------------------------------------------------------------------------- | -------- | ------ | ------ |
| C03 | Severity is invisible in fixed chrome — status/warnings paint every tone the same amber | **high** | S      | polish |
| C09 | Meter color encoding weak on clip cap, over-vs-clip, and peak-hold tick                 | **high** | M      | polish |
| C10 | Bone (light) theme fails AA on muted text, accent-on-accent-soft, solo label            | **high** | M      | polish |
| C22 | Disabled = `opacity:0.4` everywhere drops already-muted captions below legibility       | medium   | M      | polish |
| C12 | Mute/Solo lane toggles undersized (24px) and low-contrast at rest                       | medium   | S      | polish |

**C03 — Drive `status.tone` into the chrome** · `AudioTopBar`, `AudioSignalCanvas`
`describeAudioStatus` already returns a first-class `tone` (error / attention / ok — CONSOLE UNREACHABLE and RME METERING OFFLINE are `error`) and it is plumbed through `viewModel.status`, but neither surface consumes it: `.statValue` is always `var(--fg)`, `.statDot` is binary `--meter-low`/`--accent`, and `.warningBand` is hardcoded `--accent-soft`/`--accent` with no `[data-tone]`. So OFFLINE and VERIFIED look near-identical (a 5px amber dot apart) and a hard fault renders like a pre-flight reminder — even though the sibling `.feedbackBanner[data-tone="error"]` already branches to `--danger`.
**Proposal:** (1) Top bar: add `data-tone={viewModel.status.tone}` to the `.statValue` span; add `.statValue[data-tone="error"]` → dot `background:var(--danger)` + glow reusing `var(--danger-soft)`, bump dot to ~7px (fits the 56px topbar). **Keep** the value text at `--fg` for all tones (drop the candidate's `ok → --fg-2` recolor, which needlessly dims the most-shown VERIFIED readout). (2) Warning band: `data-tone` + `.warningBand[data-tone="error"]` mirroring `.feedbackBanner` (`--danger-soft` bg, `color-mix(--danger,--line)` border, `--danger` strong, re-tinted recovery buttons). `--danger` is defined in all three themes. This uses the redesign's sanctioned clip-only red — **not** a reversal of the retired multi-hue palette. Keep text labels for monochrome redundancy.

**C09 — Three safety-critical meter encoding gaps** · `AudioMeterCanvasOverlay`, `AudioStereoMeter`, tokens (verified from OKLCH math; meter interiors are magenta-masked in baselines)
(a) Clip cap vs body = **2.15:1 Studio / 1.99:1 Bone** — the at/over-0 dBFS boundary carried almost entirely by hue. (b) Canvas `meterPointOver` vs `channelPathClip` = **1.27:1 Studio / 1.01:1 Graphite** — a transient over-sample is perceptually identical to a latched channel-path clip, and they're independent non-exclusive draws that overlap geometrically. (c) Live peak-hold tick vs cream body = **1.38:1**, and the separating glow the CSS `.meterPeak` has is force-`opacity:0` on the live canvas.
**Proposal (token-only, no new hues):** (a) Hit ≥3:1 **per theme, in opposite directions** — Studio: drop `--meter-hi` to ~`oklch(52% 0.25 27)` (→3.15:1); Graphite: smaller drop ~`oklch(54–56%)`; **Bone (dark body): RAISE the cap to ~`oklch(72% 0.24 27)`** (the candidate's "drop to ~48%" is backwards and regresses to 1.57:1). Add a tunable `--meter-clip-edge` token. Do **not** darken the body ramp instead (collapses Studio to 1.04:1). (b) Re-render `meterPointOver` as a thinner desaturated **intermediate** band via `--meter-over-tone` (an orange-red `color-mix` of `--meter-hi` toward accent — must read distinct from BOTH the saturated clip-red AND the existing amber `peakWarning` outline, so not pure amber); offset it a hair vertically so it doesn't sit exactly under the clip outline. (c) Give `drawPeakLine` a 1px keyline/halo via `--meter-peak-edge`, **theme-aware** (dark halo on light bodies, light halo on Bone's dark body). Mirror all deltas per theme.

**C10 — Bone theme AA failures** · tokens (Bone), `AudioMixerLane`, `AudioSnapshotDeck`, `AudioInspector` (Bone is unbaselined, so never caught visually)
`--fg-3` (rgba(26,24,20,0.44)) composites to ~2.7–2.8:1 and carries real text (eyebrows, output pairs, snapshot preview, resting SOLO/MUTE glyph). `--fg-4` (~1.6:1) is used for real labels (Slot N, timestamps, shortcut, metric grids). Accent-on-accent-soft fails on the elements the operator most needs: **loaded snapshot tile name, Outputs tier label, active tier chips** all ~3.68:1. Solo-active = `--bg` on `--accent` = exactly 3.75:1 for the 10.5px SOLO glyph. (Correcting the candidate: the selected-lane name sits on white `--strip-bg-selected` = 4.27:1, a borderline pass, not on accent-soft.)
**Proposal (AA-blocking, gated to the light theme, luminance-only):** (1) Raise Bone `--fg-3` 0.44→~0.60 (≈4:1). (2) Stop using `--fg-4` for **text** in Bone — move snapshot slot/meta/shortcut, lane preamp/index rows, output metric small up to ≥`--fg-3`; reserve `--fg-4` for hairlines/dots/thumbs. (3) Fix accent-on-accent-soft on the real offenders — **preferred:** darken Bone `--accent` #c25e1e → ~#a64e16 (≈5.6:1 on panels, ≈4.8:1 on accent-soft) which **also** lifts solo-active to ≈4.95:1 in the same move; **alternative** (keep the warm hue): add a per-theme `--on-accent` token (Bone = dark text) and render selected/loaded **text** in `--fg` on light themes. The 8.5→9.5px caption bump is **optional, not required for AA** and touches fixed-height zones — ship only after confirming no reflow. Cross-theme: nudge Studio/Graphite `--fg-3` ~0.44/0.42 → ~0.50. Add a Bone visual baseline afterward.

**C22 — Disabled collapses to `opacity:0.4` everywhere** · `AudioMixerLane`, `AudioTopBar`, `AudioMonitorBar`, `AudioSnapshotDeck`, +9 more (13 total)
There is no disabled-opacity token. The disabled buttons label at `--fg-2`; at 0.4 opacity they composite to **2.14:1 Studio / 1.78:1 Bone** — below the 3:1 UI floor — and `actionsAllowed` is a single gate, so many controls dim at once on read-only screens. The genuine compounding case: MonitorBar `.controlSub` sub-labels (`--fg-4`) under a disabled button fall to ~**1.19:1** (invisible).
**Proposal:** (1) Add `--control-disabled-opacity` and replace the ~13 hardcoded rules. Note ~0.55 undershoots Bone (2.29:1) — use ~0.65–0.7, **or** (cleaner) stop compounding by setting the disabled label color toward `--fg`/`--fg-2` plus a modest ~0.6 opacity; verify across all three themes. (2) Promote disabled `.controlSub` sub-labels to `--fg-3` (or don't inherit the parent opacity) → ~2.2:1. **Drop the footer item** from the candidate: `.healthCommand:disabled` is a dead selector (the footer hints are `<span>`s, never disabled) and the footer's faintness is a deliberate eyebrow choice — the "4-of-10 shortcuts" redesign is scope creep on a false premise.

**C12 — Lane M/S toggles undersized & low-contrast at rest** · `AudioMixerLane`
`.laneToggle` is `color:var(--fg-3)` on `var(--bg-3)` with the readable state only on `:hover` — resting glyph ≈ 3.77 Studio / 3.55 Graphite / **2.72 Bone (fails AA)**. The buttons are ~49px wide on a fixed mouse workstation, so the 24px height already clears WCAG 2.5.8; the height bump is a minor optional win, not a defect.
**Proposal:** Lead with the resting-legibility fix — `.laneToggle` resting `color:var(--fg-3)` → `var(--fg-2)` plus a resting affordance (1px `var(--line)` border or lighter `var(--bg-elev)` fill) so M/S read as buttons without hover (resting contrast → 5.2–7.1 across all themes; Bone 2.72→~5.2). Keep `:hover → --fg`; leave active mute/solo exactly as-is. Optionally nudge height 24→~28px (not 32) and font ~11.5px — keep modest, since at 1080p the only absorber is the already-compressed `.laneBody`.

### 3. Operator speed & ergonomics

| ID  | Title                                                            | Impact   | Effort | Kind        |
| --- | ---------------------------------------------------------------- | -------- | ------ | ----------- |
| C04 | No persistent SOLO indicator and no clear-all accelerator        | **high** | M      | restructure |
| C15 | Master monitor level has no keyboard/wheel access                | medium   | M      | restructure |

**C04 — Persistent SOLO indicator + clear-all accelerator** · `AudioTopBar`, `AudioSignalCanvas`, `useAudioKeyboardShortcuts`, `buildAudioPaletteActions`
Solo is the single most consequential latched live-desk state, yet its only at-a-glance cue is a conditional amber band **inside** the `overflow:hidden` canvas (it reflows the mixer down when it appears) plus the small per-lane S. The persistent top-bar cluster carries no solo count, and there is **no plain-key clear-all-solo** (clear-clips has ⌥C; the palette clear-all-solo entry has no shortcut). `clearAllSolo` and `healthStats.soloedChannels` are already threaded.
**Proposal:** (1) Add a **persistent** SOLO `statCell` to the topbar cluster (alongside Console/OSC/Metering) — always present, neutral `0`/`—` when `soloedChannels===0`, value+dot switch to `--danger` when >0, cell becomes a button calling the wired `clearAllSolo` (guard `actionsAllowed`). Always-present, not appear-on-solo, or the indicator is itself conditional. Keep the verbose canvas band as the explainer (a test asserts it contains "solo engaged"). (2) Add **⌥S** clear-all-solo in `useAudioKeyboardShortcuts` (parallels ⌥C, ⌥S currently unbound; `s` = toggle solo, no collision), guarded by `soloedChannels>0`; assign `shortcut:'⌥S'` to the palette entry; render `<kbd>⌥S</kbd>` on the band's "Clear all solo" button. `--danger` is already the clip/mute semantic — no retired-hue reversal.

**C15 — Master monitor level has no keyboard access** · `AudioMonitorBar`
The master level is set entirely by `onPointerDown` on the L/R **meter band** mapping **absolute** pointer-X to gain — no `role`, no `aria-value*`, no `tabIndex`, no `onKeyDown`/`onWheel`, `cursor:ew-resize` across the whole band with no visible thumb. It is the **only** continuous control on the page without keyboard access (every channel/output fader is a real `AudioSliderControl`), and a tap to read the meter jumps the gain. Second defect: it writes a raw **linear** ratio straight to `volume`, bypassing the `snapFaderValue`/unity-snap dB curve the lanes use — so the master is on a different value curve.
**Proposal (lowest-risk, keeps footer no-scroll):** Add `role="slider"`, `aria-valuemin/max/now`, `aria-valuetext={masterDb}`, `tabIndex=0`, and `onKeyDown` (Arrow=step, Shift/Page=coarse, Home/End) to the band; switch the drag from absolute-on-press to **relative**; route the committed value through the same normalized model (`snapFaderValue`/`AUDIO_FADER_UNITY`) so the master shares one gain curve. The intentional dead-code `AudioRail.tsx` already demonstrates the exact pattern (same draft key, same `commitMixTargetContinuous`) — **replicate it in the live MonitorBar, do not mount AudioRail.** Cleaner alternative (more layout risk): a dedicated `AudioSliderControl` handle row, but preserve the L/R meter + dB ticks and verify the footer height at 2560/1080. Preserve the `!selectedMixTarget || !actionsAllowed` disable and reflect it in `aria-disabled`.

**C06 — Inspector tabs are mouse-only** · `AudioInspector`, `AudioInspectorTabStrip`, `useAudioKeyboardShortcuts`
The keyboard layer wires channel select, M/S/U, ⌥C, banks, snapshot recall, ⌘S, sync — but the only tab key is Escape (collapse to Preamp). After selecting a channel by keyboard, reaching EQ/Dyn/Routing forces a mouse trip. `setInspectorTab` is already threaded.
**Proposal (corrected — original named non-existent ids):** Add four plain-key accelerators after the `isEditableTarget` guard, using the **real** tab ids (`"channel"|"eq"|"dynamics"|"sends"`): **P/Q → `channel`** (Preamp), **E → `eq`**, **D → `dynamics`**, **R → `sends`** (Routing). Guard behind `viewModel.selectedChannel` (inert when only a mix target is selected — `outputSelectionOnly` forces the tab back to `channel`). No collision with m/s/u. Keep Escape. For discoverability, **prefer the established hint surfaces** over cluttering the dense 4-tab strip: add the hints to the footer shortcut group (`AudioHealthBar`, reusing its `<kbd>`) and/or the `?` overlay, plus `aria-keyshortcuts` + `title` on each tab button. Only if visible per-tab chips are still wanted, add one scoped `.inspectorTabs kbd` rule with existing tokens.

**C17 — Active mix-target context isolated far-right** · `AudioTieredMixer`, `AudioMixerLane`
Every input/playback fader edits the send to the selected mix target, but the only "Mix for → Main Out" label lives in the Outputs tier header on the far right; the Inputs/Playback headers carry only group chips + bank pill, and the per-fader readout shows a bare dB. So "which bus am I changing?" is not co-located with the left-side faders being ridden. (Correcting the candidate: the footer "Monitor →" **cannot** disagree — both derive from the same `viewModel.selectedMixTarget`. The justification is co-location distance, not a mismatch.)
**Proposal:** Echo the active mix-target on the Inputs and Playback tier headers, reusing the existing `tierMixForEyebrow`/`tierMixForArrow`/`tierMixForName` classes verbatim (already tokenized/theme-safe). Pick **one** phrasing ("Mix for → {name}" or "Sending → {name}") and apply it identically. **Layout is the real risk:** the source-tier `.tierLabel` `auto` column already packs group chips + bank pill, both `justify-self:end`; do **not** drop the verbose pill in as a third sibling. Associate the eyebrow with the title block (the `1fr` column), and gate verbosity via the existing `@container operator-root (max-width:1600px)` query — full name at 2560, collapse to `shortName` at narrow widths. Verify the 1920 + Studio-Preview baselines gain no scrollbar/wrapped row.

| ID  | Title                                                                             | Impact   | Effort | Kind   |

**C05 — Typed numeric entry missing on knobs** · `AudioKnob`, `AudioInspectorEqBandGrid`, `AudioInspectorDynamicsTab`, `AudioInspectorChannelHardwareCard`
Every other value control opens a numeric dialog on double-click + Enter (`AudioFader`, `AudioStripPreamp`, `AudioPreampControl`), but `AudioKnob` — used for ALL EQ gain/freq/Q, Low Cut, the five dynamics params, **and** the mounted inspector preamp hero — imports no dialog; its double-click only **resets to default** (so double-tapping the EQ gain knob silently flattens the band, and the freq knob — no `defaultValue` — is a dead no-op). Preamp gain is type-able from two surfaces but not the third (the hero).
**Proposal:** Add an optional typed-entry path to `AudioKnob` mirroring the siblings exactly — double-click **and** Enter both open `AudioNumberDialog`, reusing the existing `snapToStep` plumbing (integer-only preamp stays integer). Relocate reset to **Alt+double-click** and keep Backspace/Delete (already wired). **Correct two flaws in the original:** (1) do **not** derive the dialog suffix from the knob's `format` (formats bake value+unit and rescale, e.g. "8.00 kHz") — operate in **raw engine units** with explicit per-site suffix ("Hz"/"dB"/":1"/""); (2) wire all three **live** sites (EqBandGrid, DynamicsTab, ChannelHardwareCard hero) — the EqBandTray/EqLowCutTray are unmounted dead code, skip them. Simplest de-risking: make typed-entry the AudioKnob default (gated on presence of bounds, which all sites have).

**C14 — No hover affordance / detached drag feedback** · `AudioKnob`, `AudioStripPreamp`, `AudioSliderControl`, `AudioMixerLane`, `AudioFader`
The two `.knob` classes have only `cursor:ns-resize` + a post-click focus ring and **no `:hover` rule** — the one interactive class with zero pre-interaction signal on a tooltip-less panel (the fader cap, lane, EQ cards, EQ `.eqPoint` all brighten on hover). `.sliderControl` is `cursor:pointer` only. Strip faders render `showValue={false}` and the only echo (`.laneReadout`) sits below the meter offset 39px from the cap. (Correcting the candidate: the inspector `.sendCardValue` is a **persistent** readout, not a transient badge; both surfaces already echo the live draft during drag — the gap is **co-location**, not presence.)
**Proposal (primary, high-confidence):** (A) Add a `:hover` rule to `.knob` in both knob modules at the existing 0.12s timing — subtle accent-tinted ring (`box-shadow:0 0 0 1px var(--line-2)`) and/or lift the indicator. (B) On `.sliderControl`: `cursor:pointer → grab`, add `grabbing` while dragging (precedent: `.eqPoint`), lift the resting cap indicator toward `--fg-2`/`--fg-3` (cap height bump explicitly optional). No test asserts cursors/cap dims → zero-risk. **Secondary/optional:** a transient drag-only value bubble next to the cap behind a `showDragValue` prop reusing the existing `localDraftValue`/`pct` (absolute-positioned, no reflow) — frame as a co-location win, keep the resting `.laneReadout`.

**C13 — Control family divergence** · `AudioKnob`, `AudioStripPreamp`, `AudioPreampControl`, `AudioSliderControl` (severely de-scoped after verification)
The candidate's premise largely **collapsed**: `AudioPreampControl` is **unmounted dead code** (the redesign replaced the inspector hero with `AudioKnob`), so its `useRef(0)` double-tap bug and 300px drag gain are **unreachable**, and the EQ/Dyn/hero knobs are already unified at `DRAG_TRAVEL_PX=150`. The only **live** inconsistencies that survive are minor: `AudioStripPreamp`'s 120px full-sweep vs `AudioKnob`'s 150px on the **same** 0–75 dB preamp value, and the strip preamp lacking the Backspace/Delete reset `AudioKnob` has.
**Proposal:** Scope to live controls only. **Drop all `AudioPreampControl` work** (do not "fix" a bug that can't fire). Optionally promote `DRAG_TRAVEL_PX` to a shared `AUDIO_KNOB_DRAG_TRAVEL_PX` in `audioConstants` and have `AudioStripPreamp` use 150 so the two preamp surfaces share px-per-dB (confirm 120 wasn't a deliberate density choice first). Add Backspace/Delete → default to `AudioStripPreamp.onKeyDown`. Behavior-only, no layout/token change. Separately, consider marking `AudioPreampControl.tsx` dead and fixing its stale "used in the inspector" comments as its own cleanup.

### 5. Layout & density

| ID  | Title                                                                                              | Impact | Effort | Kind        |
| --- | -------------------------------------------------------------------------------------------------- | ------ | ------ | ----------- |
| C08 | Equal-thirds mixer grid wastes a horizontal band; 110px lanes don't grow                           | medium | M      | restructure |
| C11 | Stacked footers, near-empty context bar, stackable warning bands spend vertical budget             | medium | M      | restructure |
| C21 | Top bar pools slack into one dead gap; snapshot/clip chrome footprint & hover-only discoverability | medium | M      | polish      |

**C08 — Mixer wastes horizontal band** · `AudioTieredMixer`, `AudioMixerLane`
The mixer is `grid-template-columns: minmax(0,1fr) ×3` regardless of lane count (Inputs ~4, Playback ~6, Outputs 3), so Inputs/Outputs leave asymmetric voids; lanes pool left and the stereo meter wrapper is pinned at 46px — the most-scanned element under-uses the band. The meter is fully fluid inside, so widening the wrapper cleanly widens the bars.
**Proposal (corrected — original had material errors):** (1) Make columns **content-proportional, NOT count-based** — output lanes are **220px** (2×, the candidate falsely called them 110px), so a count-keyed 4.2:6:3 would **starve Outputs into horizontal scroll**. Use ~`minmax(0,4.2fr) minmax(0,6.2fr) minmax(0,6.1fr)` (content widths ~462:686:680px), or the safer fallback: keep equal-thirds and add `justify-content:center` to the tier lane grids so whitespace splits to both edges (right-pooling comes from the default main-axis `justify-content:flex-start`, not the `align-items` the candidate blamed). (2) Let **channel** lanes flex (`.channelLane` → `flex:1 1 110px`, max-width ~140px, min-width 88px); leave `.outputLane` at 220px. Bump the meter wrapper 46→~52px. The containment test only checks vertical overflow and grids are `overflow-x:auto`, so tests hold — but verify 1920 and confirm Outputs gains no horizontal scroll.

**C11 — Vertical budget spent on chrome** · `AudioWorkspace`, `AudioMonitorBar`, `AudioHealthBar`, `AudioSignalCanvas`
`.laneBody`/`.outputBody` are `flex:0 1 280px` and shrink at 1080p, so surrounding chrome directly compresses faders/meters. Real wins: (b) `.canvasContextBar` (~38px hairline row) holds only an optional meter chip + spacer + Hold/Reset, and the chip is **already** surfaced in the topbar Metering cell — largely redundant; (c) the top warning band + solo band + clip band can stack to ~110px of bordered rows directly above the meters exactly when meters matter. **C07 — Module-wide token fork** · `AudioWorkspace.module.css`, `AudioInspector` (`.bigMeterCard`), the 3 inspector tabs, meter/readout/fader/tagstrip/dialog modules
